# 投递跟踪模板 v2

本轮以用户提供的投递清单截图为布局参考。模板只定义结构，不包含截图中的企业、岗位或任何演示申请；三个视图共享同一张主表。

## 主要字段

| 顺序 | 字段 | 类型与用途 |
| --- | --- | --- |
| 1 | 公司 | 文本主字段 |
| 2 | 投递岗位 | 文本 |
| 3 | 投递渠道 | 单选：官方网站、内推、招聘平台、邮件、微信公众号、校园宣讲会、其他 |
| 4 | 投递日期 | 日期字段，显示 `yyyy-MM-dd` |
| 5 | 投递状态 | 彩色单选，依据已记录的真实申请事实映射 |
| 6 | 岗位链接 | URL 样式的可点击文本链接 |
| 7 | 备注 | 人工文本，后续同步不覆盖 |

后面保留本地申请 ID、招聘批次、完整投递时间、官网原始状态、标准化阶段、招聘结果、授权/查询/同步状态、最近查询时间、下一项待办、重试次数、错误、执行状态和提交证据等辅助列。

“本地申请 ID”继续用于精确去重，即使在日常视图中隐藏也不能删除或修改。公司主字段可以重复，一份申请对应一行。

## 状态与颜色

状态选项包括：待投递、填写中、待官网审核、提交待核实、已投递（人工确认）、官网已投递、简历筛选、待测评、测评中、测评完成、笔试中/完成、面试中/完成、已发 Offer、已录用、未通过、已撤回、已结束和待核对阶段。

“官网已投递”使用浅紫标签，“测评完成”使用浅绿标签，接近参考截图。程序只映射已知的后端阶段或精确官网状态文字，不把“测评未完成”判为完成。未知提交结果优先保留“提交待核实”；人工确认和官网回执单独区分，不编造进展。

登录状态、执行状态、查询状态、同步状态与招聘阶段保持独立。`attention_status` 仍负责异常整行填色：授权缺失浅黄、重试耗尽浅红、正常不填异常背景。单选标签颜色不等于整行颜色；整行规则仍需按[飞书填色说明](feishu.md#整行浅黄--浅红)人工设置。

## 三个视图

| 视图 | 配置 |
| --- | --- |
| Grid | 前七列对应截图，后面展示全部辅助字段 |
| 投递状态看板 | 按投递状态分组，显示主要信息与下一项待办 |
| 投递清单 | 按投递日期倒序，保留主要字段与查询/同步异常信息 |

配置会复用同名、同类型视图，只创建缺少的视图，不删除其他视图。同名歧义或类型不同会停止；同名模板视图的可见列、看板分组及清单排序会按模板重新设置，因此执行前必须确认目标与影响。首次建表时平台自带的其他视图可能仍保留。

每次设置后通过对应 `+view-get-*` 回读服务器配置，支持把返回字段 ID 与已检查的字段名称对齐。回读不一致不会报告成功。创建超时先保留意图；再次执行先查找同名视图，仍查不到时停止，不盲目重复创建。

## 使用入口

- [完整模板 JSON](../examples/feishu-template.json)：字段、类型、选项、颜色和视图配置。
- [字段数组 JSON](../examples/feishu-fields.json)：与 `feishu schema` 相同。
- [空白投递清单 CSV](../examples/投递清单空模板.csv)：仅表头，用于整理和导入岗位；CSV 不携带字段类型、颜色和视图。

```bash
# 本地预览，不访问飞书
npm run dev -- feishu template

# 展示影响并确认后，新建 Base / 主表并配置视图
npm run dev -- feishu create

# 连接返回的真实坐标；确认后保存
npm run dev -- feishu connect YOUR_REAL_BASE_TOKEN YOUR_REAL_TABLE_ID

# 为已连接的新版表配置或重新核对视图；先预览确认
npm run dev -- feishu views
```

客户端入口：保存真实目标表，在“设置与连接”展开“投递跟踪模板与视图”，点击“配置模板视图”，在任务详情确认后继续。只操作已保存的目标，打开设置页不会建表或设置视图。新建主表仍沿用已有 CLI 流程。

旧版字段无需迁移即可继续同步，程序自动识别并使用原“岗位”“官网链接”“投递时间”“人工备注”等名称。想获得完整新版布局可另建模板表并明确连接；本轮没有实现既有申请在不同远端表之间的自动迁移。截图表如果只有七列，需要补齐系统字段才能作为同步目标，不能仅靠公司和岗位猜测对应关系。

## 日期、渠道与人工资料

投递日期由可靠的 `submittedAt` 按本机时区取日，写成明确的 `YYYY-MM-DD 00:00:00`，同时保留原始 ISO“投递时间”。新建 Base 使用本机时区。没有可靠时间时留空，不用导入时间、当前时间或查询时间代替。旧版继续使用 ISO 文本字段。

岗位导入支持截图中的“投递岗位”“岗位链接”“投递渠道”“备注”表头；XLSX 的链接显示文字与真实超链接沿用现有解析。导入的日期和状态不会被当作官网回执或已提交证明，导入仍只建立岗位。渠道未提供时留空，不把文件来源冒充投递渠道；如果渠道不在目标单选项中，请先补充选项或使用已有项。

备注和明确提供的渠道仅在首次创建行时初始化，后续同步只回读人工修改。截止时间、优先级和暂停跟踪继续由人工管理，旧“人工备注”也可读取。

## 接口依据与验证边界

已核查本机 CLI 1.0.78 内置 `lark-base-field-json.md` 和 `lark-base-cell-value.md`：日期使用 `datetime`，URL 使用 `text` 的 `style.type=url`，单选用 `select/multiple=false`。视图按[官方 CLI 实现](https://github.com/larksuite/cli/blob/v1.0.78/shortcuts/base/view_ops.go)配置和回读。

本轮真实 CLI dry-run 已检查建表、建视图、列顺序、分组和排序请求；测试使用显式临时传输替身验证同步、恢复与回读。这些结果不代表真实飞书表格已创建或生产联调已通过。本轮没有用户目标表链接，没有修改真实飞书表格或发送申请。
