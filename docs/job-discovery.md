# 官网岗位发现与 AI 筛选

入口：**投递工作台 → 官网找岗位**。这是已接入客户端的功能；原有 CSV / TSV / XLSX 导入继续可用。

## 使用步骤

1. 在“简历与资料”导入简历，确认需要用于匹配的教育、技能、项目和工作／实习内容。
2. 进入“官网找岗位”，选择腾讯社会招聘、字节校园招聘／实习中的一个或两个，填写关键词、城市、招聘类型。毕业届别与相关经验年数可不填，不能由程序猜测。
3. 选择一个简历版本，以及每站最多 3、5 或 10 个 JD。本次只读取各站搜索首页前 N 条，按官网默认顺序取回；不是全站扫描。
4. 可选择本地条件筛选，或 AI 对照。AI 复用“设置与连接”的模型名称、HTTPS 端点和 Keychain API Key；支持现有 Chat Completions 兼容协议。字段映射开关与本次资料披露是不同授权。
5. 点击“预览并准备启动”。AI 模式会展示将发送的具体资料、模型地址与名称。核对后勾选本次披露确认，才可启动。预览 10 分钟有效，简历或模型设置变化会使其失效；不能重放。
6. 结果按“优先查看、可以考虑、信息待补充、暂不匹配”排序。展开对应岗位，核对 JD 原文和简历原文，再“加入工作台”或“暂时跳过”。原文可在系统浏览器打开。
7. 加入工作台只保存岗位；选择“前往工作台继续”后，仍需走已有的简历选择、网站披露、辅助填写、本人官网审核提交和回执核查流程。

## 实际接线

| 位置                                        | 职责                                                                                            |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `src/discovery/sources.ts`                  | 官网搜索、只读导航约束、匿名 Chrome 上下文、列表到详情、职责／要求／加分项提取                  |
| `src/discovery/match.ts`                    | 已确认资料摘要、联系方式隐藏、本地条件、独立模型请求、Zod 输出和原文引用校验                    |
| `src/discovery/service.ts`                  | 一次性启动预览、版本绑定、单次采集预算、Keychain 持久化、用户选择和岗位去重                     |
| `desktop/contract.ts`、`desktop/service.ts` | `discoveryPreview / discoveryView / discoveryDecision / discoveryOpen` 与 `start(discover)` IPC |
| `desktop/renderer/DiscoveryPage.tsx`        | 偏好表单、资料披露、任务控制、结果筛选、原文对照、加入工作台                                    |

腾讯从只读岗位卡片打开详情弹窗；字节从列表中读取官方详情链接。新 Chrome 上下文不访问已有申请登录目录，不接入官网 AI 助手，也不点击登录、收藏、投递按钮。采集导航仅允许已支持的官网搜索和详情路径。站点需要验证码、未加载、无可确定结果或结构变化时，显示采集未完成，不推断岗位下架。

## 判断和资料边界

- 本地规则只处理明确的城市、招聘类型、唯一毕业届别和可识别的经验年限。偏好／加分条件不作为经验硬拒绝。未知保留待核查；学历、专业、技能等由 AI 结合原文判断或由本人阅读，不以简单关键词覆盖所有复杂资格条件。
- AI 只看到预览中的事实值、相关偏好和公开 JD。不发送附件、姓名字段、学校／雇主名称字段、邮箱／电话字段或识别来源；允许的经历文字会隐藏邮箱、电话及链接，但仍须本人检查是否包含其他不想披露的内容。
- 最多 40 项事实、合计 10,000 字，每项最长 1,800 字，界面预览就是实际发送范围。无法完整读取或过长的 JD 会明确跳过，不把列表摘要当作完整 JD。
- AI 输出必须通过结构校验，每条 JD 引用和对应资料引用必须能逐字核对。虚构引用、模型错误、超时或响应过大时保留 JD，标为分析未完成。建议是求职参考，不表示录用概率。
- 本地确定不符的岗位不调用模型；“信息待补充”不能因为模型给出推荐就悄悄消失。存在本地未知条件时，最高优先推荐降为“可以考虑”。
- 每站最多 10 个 JD、每次最多 20 次模型请求、单次模型超时 45 秒、响应上限 100 KB、整个任务限时 12 分钟。可暂停、继续、取消；取消中断浏览器与模型请求，已保存结果保留。
- 推荐及资料摘要保存在本机 Keychain，SQLite 仅记录任务元数据和用户选入的岗位。只保留最新一批推荐；新批次替换旧结果，已选入工作台的岗位不删除。重复选择不会重复建立申请或同步任务。
- 简历或模型配置变化后，已有结果标为过期。系统不会静默切换默认简历、自动开始投递或最终提交。

## 验证与当前限制

自动化覆盖 IPC、独立披露确认、过期与重放拒绝、资料范围、引用验证、规则边界、异常降级、取消保留、去重与无申请／同步副作用、官网 DOM 提取和腾讯弹窗导航。Renderer 验证选择、披露、加入工作台及 1440 / 1280 / 1024 / 390 宽度下的溢出。DMG 内 App 测试也覆盖入口、真实 IPC 预览和结果读取。

本地验证通过：TypeScript 检查、114 项单元测试、28 项浏览器测试、9 项 Electron／打包 App 测试，含新入口的真实 IPC 预览。本轮本地打包为 Apple Silicon，两个架构的 DMG 挂载与复制后验收由 CI 继续执行。

2026-09-10 使用编译后的采集模块，以“后端”为关键词，在匿名 Chrome 中分别读取腾讯与字节搜索首页首条：腾讯“腾讯云研发效能-后端开发工程师”，字节“Agent后端开发工程师 - Aime”。两站职责与要求均成功读取。这是小范围公开网页联调，不代表整个站点、所有地区或未来页面版本一直可用。

本轮没有使用用户真实简历调用远端模型；模型边界和响应验证使用合成资料与受控响应。没有新增自然语言追问、多简历联合比较、任意官网适配、全站分页、长期推荐历史、跨批次模型缓存、薪资／到岗时间硬规则或自动定时采集。这些属于[后续设计](job-selection-agent-plan.md)，不能当成已交付能力。
