# 简历经历解析与网申字段映射

简历导入分为三步：按版面恢复 PDF 文字顺序（扫描页使用本地 OCR）、将章节拆成可核对的经历记录、在本人确认与绑定后映射官网字段。三个步骤共用原有资料 schema、Keychain 和填写引擎，不需要模型 API，也不会向搜索引擎或云模型发送简历内容。

## 公开字段依据

本轮查询日期为 2026-09-08。参考以下第一方公开资料整理字段名称与区块别名：

- [华为招聘公开简历表单](https://career.huawei.com/reccampportal/campus4/pages/resumeManager/resumeManager.html?lang=zh_cn&projectName=%E5%AE%99%E6%96%AF%E9%A1%B9%E7%9B%AE&type=1)：教育信息将院校、专业、在校时间、学历与学位分别收集。该页面是公开的历史入口，不能当成当前所有华为招聘入口的适配证明。
- [智联招聘官方隐私说明中的简历字段](https://rd6.zhaopin.com/aboutus/legal/privacy)：公开列出了教育、工作/实习、项目等简历模块及相应的名称、时间、职位与描述字段。这里只参考字段定义，没有注册、授权或提交真实简历。

| 官网字段所在区块    | 内部资料字段                                                                      | 处理原则                                           |
| ------------------- | --------------------------------------------------------------------------------- | -------------------------------------------------- |
| 教育背景 / 教育经历 | `education.<id>.school / major / qualification / degree`                          | 学历与学位分开；写着“本科”不等于已经获得学士学位   |
| 教育背景 / 教育经历 | `education.<id>.startDate / endDate`                                              | 保留原始年、月、日精度；不补造日期                 |
| 工作经历 / 实习经历 | `experience.<id>.company / title / startDate / endDate / description`             | 每个单位单独建记录，职责内容保留为可编辑长文本     |
| 项目经验 / 个人项目 | `project.<id>.name / role / startDate / endDate / description / responsibilities` | 项目描述与明确标注的个人职责区分，未注明的角色留空 |
| 求职意向            | `preference.role / preference.location`                                           | 只使用本人简历中明确给出的信息                     |

默认规则位于 `examples/field-mappings.json`。`sectionAliases` 补充“教育背景”“工作经历”“项目经验”等区块名称；字段仍在区块内匹配。多个不同资料路径同时命中时继续要求人工确认，不选择第一个猜测值。如果配置了自定义 `mappingFile`，它仍优先，需要将需要的新规则合并到自己的文件中。

这些是语义映射，不包含未经验证的 DOM 选择器、登录规则、翻页规则或提交回执。不同官网的下拉框、日期控件和重复区块结构仍需观察或配置，不能据此声称已适配任意官网。

## 本地解析与核对

- PDF 文本按页面坐标合并成行，修复绘制顺序与阅读顺序不一致造成的章节、日期错位。扫描页继续使用 macOS Vision。
- 识别教育、工作/实习、项目、专业技能与开源实践等常见标题；处理中文兼容字形、标题中的空格和日期分隔符。
- 经历按名称和起始时间等来源信息生成稳定记录 ID，同一简历重复导入不追加同一经历。改动已确认值时显示冲突；未识别到的字段不清空已确认值。
- `records.project` 是原 version-1 schema 的兼容扩展；旧资料读取时默认空数组，无数据库迁移。旧的教育、实习和自定义 facts 保持可读。
- 候选字段可查看对应的简历原文依据，依据与资料值一起保存在 Keychain。数据库版本记录和任务事件不写入经历正文，搜索和模型映射接口不接收简历内容。
- “我的资料”按每段经历显示字段，长描述使用多行编辑框。确认后，任务抽屉显示名称与时间范围，用户将官网的经历区块绑定到具体记录。
- 日期仅到月份时，月份控件可直接填写；官网要求完整日期时等待本人补充。“至今”保留原意，不能自动编造离职时间。

规则解析仍有边界：复杂多栏、旋转文字、无章节标题、模糊扫描和未明确标注的角色/职责可能需要人工补充。没有实现云端语义解析，不能保证所有简历都能完整结构化。

## 验证方式

公开测试只使用 `tests/resume-fixture.ts` 的虚构简历，覆盖多段经历、日期精度、冲突、重复导入、旧 schema、区块别名、客户端编辑和真实 Chrome 填写。用户提供的真实 PDF 仅在隔离的本地目录中验收，不加入代码、测试样本、截图文档或 GitHub 提交。实际结果见 [桌面验收记录](desktop-verification.md)。
